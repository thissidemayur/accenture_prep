# PART 1 — PROCESS BASICS

## Q1. Process Creation

A C program needs to create a child process and then run `/usr/bin/python` inside that child. Which pair is most appropriate?

A) `open()` and `close()`
B) `fork()` and `exec()`
C) `wait()` and `exit()`
D) `pipe()` and `read()`

**Answer: B**

**Why:** `fork()` creates the child; `exec()` replaces the child process image with the requested executable.

**Options:**
- A → file operations
- B → process creation + program execution
- C → waiting/termination
- D → IPC/pipe operations

# PART 2 — THREADS AND PROCESSES

## Q11. Shared Thread Data

Threads belonging to the same process generally share:

A) Stack
B) Program counter
C) Heap
D) CPU registers

**Answer: C**

**Why:** Threads share the process's address-space resources such as heap/data/code, while each thread has its own stack, registers and program counter.

# PART 8 — HIGH-RETURN TRAPS

## Trap 1: fork vs exec

```text
fork() → creates child
exec() → replaces process image
```

---

## Trap 2: Orphan vs Zombie

```text
Parent dies first
→ Orphan

Child dies first
+ parent hasn't collected status
→ Zombie
```

---

## Trap 3: Ready vs Waiting

```text
Ready   → waiting for CPU
Waiting → waiting for I/O/event
```

---

## Trap 4: Mutex vs Semaphore

```text
One-at-a-time access → Mutex

N available permits/resources → Counting semaphore
```

---

## Trap 5: Page Fault vs Segmentation Fault

```text
Page fault
→ required page isn't currently available in physical memory
→ OS may handle it normally

Segmentation fault
→ invalid/prohibited memory access
→ usually terminates offending process
```

---

## Trap 6: Process vs Thread

```text
Process
→ stronger address-space isolation

Thread
→ shares process resources

Shared → heap/code/global data
Separate → stack/registers/PC
```
